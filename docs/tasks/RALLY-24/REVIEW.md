Proposed recurring road/car submission is **147 wire bytes/frame**, excluding unchanged scenery/HUD/audio/swap and diagnostics. This is calculated from the proposed format, not a measured speedup. Car projection can move alongside road projection. Finish-line, signs and crash placement also consume projected centres; move their existing visual calculations with the renderer rather than introduce screen-coordinate readback. This is dependency closure, not new traffic AI, collision logic or a new effects system.

Candidate A will retain that arithmetic as a compatibility control while moving host projection/command generation. Compare both before concluding whether native arithmetic or fewer UART writes supplies the gain.

A is only an intermediate/control and cannot satisfy the completed first pass. The next proposed tranche is local implementation/build/checks, with no hardware or emulator changes, pending approval.

## 2. Native arithmetic and numerical compatibility

1. Host road lookup computes fractionQ14, fractionQ12 and squared fraction with integer truncation, then `a*4 + b*f/4096` and `c + d*f/4096 + e*f²/4096`. Section centres round signed half pixels away from zero. Dividing a negative signed value cannot be replaced by a shift without proving equivalence.
2. Current buffered section templates contain five coloured strips when marked, four otherwise. A 4×4 transform derives the vertices. Candidate B must preserve the actual binary32 expression/evaluation and signed endpoint conversion where it affects pixel boundaries; the mathematically simplified expression is not automatically pixel-identical.
3. The pinned VDP `types.h::convertFloatToValue` casts floats directly to unsigned words. Negative/out-of-range conversion is a portability hazard already encountered in Extender work. Do not copy that undefined case into the module or repair upstream silently. Capture classic-Xtensa behaviour for bounded valid coordinates and implement explicit signed/range-checked conversion. If exact pixels require an unresolved rounding policy, stop B while retaining A as a diagnostic control; obtain review before relaxing visual acceptance.
4. eZ80 ordinary `int` and pointers cannot define the wire layout. Use explicit fixed-width fields and byte loads/stores. Cross-check multiplication bounds for all legal world states. Native code must not accidentally import libgcc helpers, malloc, memcpy or C++ support unavailable to the module linker. Builder uses `-nostdlib`, `--no-undefined`, `-ffp-contract=off`; later disassembly/link checks are mandatory.

## 3. Runtime audit

The inspected runtime executes native code synchronously in the command task. Acquired buffers have shared ownership during the lease; arguments are protected from write aliases. Leases/pointers end at return. Commands following RUN cannot parse until it returns, but prior Canvas drawing can still be queued.

Use separate data/output buffers, never patch the executing wrapper, argument block or bitmap storage. Generated commands contain copied coordinates or stable bitmap/matrix IDs. Audit ordinary matrix/bitmap primitives for queued references before allowing resource changes; no module unload, asset mutation or track switch until outstanding graphics work is drained.

Stock conditional CALL and jump-to-end solve two otherwise important problems: guard output with a flag cleared before RUN, and terminate a variable-length command list before stale tail bytes. These features exist in the pinned exported `vdu_buffered.h`, not just current documentation. Native failure before entry leaves readiness false; partial native output remains uncallable. A native crash or infinite loop is outside this guarantee: there is no process isolation or forced cancellation.

No generic callback service is needed for stage 1. RALLY-25 must separately resolve event delivery; current native service table cannot directly send arbitrary keyboard packets. Discovery/LOAD replies already use the keyboard packet route; keep their token handling separate from actual input and EMOS handling.

Module limits include rodata inside the 4 KiB budget. Large lookup/header arrays must be resident VDP buffers, not `#include`d into module constants. Four live buffer leases suffice with the schedule in DESIGN. Package data and executable heaps are distinct resources; total free RAM alone does not establish loadability. Espressif documents capability-specific heaps and 32-bit-only accesses for MALLOC_CAP_32BIT, used here for executable storage. [ESP-IDF 4.4.6 heap documentation](https://docs.espressif.com/projects/esp-idf/en/v4.4.6/esp32/api-reference/system/mem_alloc.html)
