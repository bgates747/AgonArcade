## Adapter contract

One JSON request/reply per subprocess invocation, no shell. Requests carry schema1, run UUID, monotonic sequence, action and optional explicit timeout; replies echo all identity fields. Every reply includes fresh mainboard/P4 boot identities, unchanged read-only startup hash, committed route, separate actual mode descriptors, resident foreground, visible-CLI status and commissioned runtime pins. Required capabilities match coordinator.CAPS. Accepted actions are snapshot, select_route, select_mode, launch completion and persistent status notification; no other device operation is exposed.

Launch verifies deployed input hashes and unused output files, explicitly invokes only the supplied job, and returns accepted_job. Completion supplies job_id, returned, inputs_verified, exact executable hash, a local result directory and hashes for **every required output**. The coordinator verifies those raw bytes, parses all frame rows/diagnostic equations and rejects incomplete outcomes; physics compares all420fields to the independent capacity reference. Peer restart or uncertain completion suppresses restoration input too. Protocol/source/receipt validation is not physical adapter acceptance.
