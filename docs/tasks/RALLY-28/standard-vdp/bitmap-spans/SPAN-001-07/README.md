# Finite matched road benchmark

This isolated application compares shared-lookup buffered polygons, bitmap spans with the original stripe arithmetic and bitmap spans with the exact row-phase lookup. It is finite, saves its own results and restores a single-buffer entry mode/visible CLI. The normal game, visual demo and old fixtures are unchanged. Final evidence/limitations are in the parent benchmark results.

## Frozen workload and cases

`HOST-POSES.json` defines128full-Fuji poses: position `(pose*25600+1360)%3276800`, stripe phase `((pose+1)*1360)%8000`, and centred/−100/+100pixel offsets in32pose groups. Full shared eZ80 projection and centre preparation occurs at runtime; poses are not preprojected in the application. Both endpoints, including row224, receive the offset. Independent host geometry/serialization checks compare captured payloads to this specification.

CPU-only cases repeat the128pose cycle eight times (1024frames); all final CPU cases last more than ten host seconds. Primary diagnostic pipeline cases use128frames, with32frames for empty brackets. All three long Flexe drawing cases failed. Short16frame Flexe probes qualify the timing mechanism only; supplementary stock-mode Fab512frame controls complete and each exceed ten seconds. Counts are fixed within each measurement axis and separately identified. Original arithmetic and lookup emit exactly the same bitmap records. Polygon proportions are matched to the selected35pixel source layout, with normal fine band boundaries; rasterization differs intentionally (band polygons versus scanline bitmaps), without a new exact-pixel gate.

The common geometry control computes all120centres and then band endpoints again. `build.py --sparse` supplies a separate `POLYGON_SPARSE=1` binary which restores on-demand polygon endpoints; its identical command stream is independently checked. This is the fair CPU/pipeline polygon control. Do not infer a bitmap win from the deliberately redundant common geometry control. See [final results](../BENCHMARK-RESULTS.md).

Config is `variant live diagnostic frames`: variant0polygons,1original bitmap arithmetic,2lookup bitmap arithmetic,3empty; live0opaque sink,1real UART; diagnostic1normal-worker VDP frame timing,0stock completion. Max1024frames. Configuration comes from a separate config.txt; no interactive hold, menu, physics scheduler, traffic/HUD/audio or automatic test resume. Setup preloads assets/matrices/templates and the coefficient table; all output files are create-new.

## Timing and commands

Geometry and parameter/command construction have separate PRT observations. Submission includes real synchronous MOS writes/CTS. Waiting ends at ordered GP232. VDP-diagnostic wrappers begin only after all frame parameters/command data arrived, perform the whole road clear/draw/bottom clear, end at the normal-worker fence and then acknowledge. VDP-local submitted/completed/drain intervals are retrieved after each bounded128frame capture, outside individual frame spans. The whole host/PRT window also includes those record-readout gaps; report it separately rather than calling it uninterrupted drawing throughput. No cross-processor clock subtraction or addition of overlapping intervals.

Bitmap records use the existing application-resident737byte envelope and resident commands. The diagnostic setup neutralizes the old resident flush/GP tail; diagnostic completion is exclusively the normal-worker frame fence. The stock path retains its bitmap flush and explicitly flushes polygons before GP. These are intentionally different timing/control modes and must not be pooled as byte-identical cross-backend performance tests. The portable hardware inputs match the Flexe diagnostic case exactly, not the supplementary Fab stock-control configuration.

Polygons upload their variable-length stored command block at exactly its actual size, avoiding padded zero-byte interpretation. The VDP executes its stored per-band parameter patches and primitive templates after the outer begin marker. This includes buffer interpretation/copies, not only pixels. Wrapper updates and clear/fence/ack requests count toward recurring traffic. The existing737byte bitmap payload is only one component of full benchmark traffic; no claimed byte saving excludes the added timing controls. Cached inverse matrices/VDP heap use and hardware qualification remain separate limits.

PRT1is claimed only if idle, its routing/reload/control/prior vector restored after capture; file saves and mode cleanup are outside frame spans. Mode selection uses a fresh query, a conditional switch to8and160nominal MOS units of settling. Double-buffered entry is refused. The Pi coordinator adds its required host-monotonic settling and authoritative route/boot/foreground checks for hardware; current hardware chain is not ready.

## Reproduction and evidence

`build.py` builds the standalone application using existing AgonDev, copying qualified shared projection headers and task-owned phase/generated data. `profiles.py` prepares fresh copied/pinned canonical Fab or Flexe launchers. `run.py` forces BOTH SDL dummy drivers, monitors boost0, preserves input/output hashes and suspension observations, bounds execution and stops only its owned process group. `batch.py` final05names are consumed; do not rerun blindly. Earlier calibration versions are labelled in VERSIONS.json and excluded from final comparison.

`verify_wire.py PROFILE --evidence` independently checks saved complete short-run render payloads against HOST-POSES.json and Python serialization; `--partial` checks exact failed long-run prefixes without treating them as completed runs. Compressed raw captures and their uncompressed hashes are under evidence/runtime. Host geometry was also run under ASan/UBSan. Firmware/source provenance is under SPAN-001-08, portable inputs/coordinator under SPAN-001-09. No physical hardware request, SD access, firmware flash or startup change occurred. Agent testing is headless/silent; no new visual acceptance is claimed. New work is uncommitted for review.
