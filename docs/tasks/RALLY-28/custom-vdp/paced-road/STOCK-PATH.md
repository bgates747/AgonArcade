# Stock VDP road fill findings

The existing firmware supports a general four-corner fill through stock PLOT221. Use that as the first comparison with paired triangles. A three-point parallelogram fill is also available, but does not represent a road band whose width grows towards the viewer. No new firmware primitive is required for this experiment, and no target speedup is yet established.

The exact deployed firmware SHA256 is `8da2ebfdfa3b5b00f4a1929ad4885c838845b160f570259792ef370b69d4f473`. The SDK build pins VDP source `1056ee38ec1cc68ed327bd32ee47d04b1c30597c` and vdp-gl `ac2dd5986daf496c43ae8e7fe41836274aec54a0`. The inspected graphics header is byte-identical to that pinned stock source. File identities and host receipts are in [STOCK-PATH.json](STOCK-PATH.json).

1. **Commands and point order.** `Context::plot()` maps operation 0x50 to triangle fill, 0x70 to parallelogram, and 0xD8 to filled path. Absolute foreground plotting adds five: 85, 117 and 221 respectively. Filled-path construction begins with the two previous graphics-cursor points and appends the supplied point. Consecutive matching path commands extend it. The quad needs perimeter order TL, TR, BR, BL; reusing the triangle-strip TL, TR, BL, BR order creates a crossed shape. Sources: [pinned graphics header](https://github.com/tomm/agon-vdp/blob/1056ee38ec1cc68ed327bd32ee47d04b1c30597c/video/context/graphics.h), `plotTriangle`, `plotParallelogram`, `plotPath`, `plot`.
2. **Closure and sequencing.** A move/different drawing operation or a next non-PLOT byte closes the path. `VDUStreamProcessor::vdu_plot()` uses `peekByte_t()` and `Context::plotPending()` for this. Resident buffered lists provide consecutive bytes without serial gaps. The next GCOL18 or final buffered RETURN23 closes a completed material; no extra terminator bytes are required in that arrangement. Keep each four-corner sequence contiguous. Probe controls include explicit move closure, end-of-input and non-PLOT closure. A delayed serial stream can close a path too early, so this is a resident-buffer experiment rather than four separate UART writes. See [official PLOT documentation](https://agonplatform.github.io/agon-docs/vdp/PLOT-Commands/#fill-path-experimental-plot-codes-d8-df).
3. **Rasterization.** Triangles, parallelograms and general paths all reach `Canvas::fillPath()`. `BitmappedDisplayController::fillPath()` computes edge intersections per scanline, sorts them and fills paired horizontal ranges. The quad is not internally split into triangles. Two triangles require two full calls with their own row/edge setup. For an unclipped horizontal band, the top boundary is excluded and the bottom included; the right edge is exclusive. This is the existing raster convention, which future adjacent material strips must share. Clipping uses the graphics viewport through the same path.
4. **Host proof.** `inspect_stock.py` extracts the unchanged point-stack, triangle, parallelogram, pending-path and scanline-fill functions and compiles them with recording stubs. All 360 sampled cases pass ordinarily and with ASan/UBSan: narrow and wide tapered bands, one-row bands, shifted/curved edges, near/horizon positions, viewport clipping, closure and matching triangle/quad pixel coverage. These sampled checks are not whole-scene visual acceptance, integration testing, firmware timing or a new exact-pixel requirement.
5. **Execution and completion.** Mode136 is double-buffered 320×240 at nominal60Hz. In the pinned graphics controller, non-swap primitives in double-buffered mode execute synchronously in `addPrimitive()`; swap goes through its queue and VSync wait. Thus the generic claim that every primitive is handed to a separate graphics worker is too broad for this fixture. Helper-ready publication establishes complete command buffers, not pixels. The guest marks after sending swap bytes, without a separate swap-completed reply; subsequent checked calls are ordered behind stream processing. Preserve these baseline boundaries and avoid calling them isolated VDP completion timestamps.
6. **Next implementation axes.** Use a stock quad fill while holding geometry/material layers constant first. Then specialize vertices to top `ct + (yt-96)*u/50` and bottom `cb + (yb-96)*u/50`, sharing each edge's center/scale and choosing documented fixed-point rounding. Independently compare non-overlapping materials: existing 4/5 layered shapes become 7/9 disjoint horizontal material intervals if all current features are preserved. That removes overwritten pixels but adds shape setup, so measure it rather than assume it wins. Finer band geometry is a subsequent disclosed speed/quality option.

The broad VDP-001 capability audit remains open. This tranche disposes only the immediate road-fill question and establishes the existing stock path; it does not prove every hand-written facility has already been audited.
