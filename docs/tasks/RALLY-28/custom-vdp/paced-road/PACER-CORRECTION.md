# Reviewed fixture pacing correction

The reviewed Rally-25 binary requests nominal 36 FPS despite its 30-Hz label. Keep this exact pacing in the first renderer comparison; changing it in only one candidate would change more than the renderer. The latest measured rates remain valid because they were already calculated at 120 MOS units per second.

1. MOS 3.0.2 increments the 32-bit clock by two for every VBlank interrupt. At nominal 60 Hz the counter advances by 120 units per second, with a 16.67 ms update period. It is not a universal 100 Hz centisecond clock. At 50 Hz it advances by 100 units per second. Rate and resolution are different quantities.
2. The tested `probe.bin` SHA256 is `7ca030245515a9aeff8949831e399d7a1baa4250237bed6f7e213477e9d8ac25`. Its `pace_frame` routine at 0x0402E1 advances an absolute deadline by 3, 3, 4 units, repeating. Three frames per ten units at 120 units/second requests 36 frames/second. The old 100-unit assumption would have implied 30.
3. Current `RALLY-25/native-demo/guest.asm` instead adds four every time, requesting 30 FPS at 120 units/second. Rebuilding that source unchanged would silently alter the comparison. The recovered `control/source/guest.asm` restores the old pacer and reproduces the reviewed binary byte for byte, including PRT and callback handling. Changes to include spelling/comments affect no emitted bytes.
4. Actual measured aggregate rates were 29.5728 FPS in the latest human Flexe run and 26.8390 FPS on C8; physical PRT agrees at 26.8938 FPS. Neither result implies that the intended 36 FPS deadline was met. The absolute deadline is carried forward; overruns make later waits expire immediately until the workload catches up. This is not a fixed-delay-after-render scheduler.
5. The first renderer candidate must keep the tested driver, four physics steps per rendering update, 900 frames, assets, diagnostics and firmware unchanged. Correcting the pacer in a new 30 FPS variant requires a separately identified control/candidate comparison. The later unpaced experiment remains separate.

The official API documentation labelled this counter centiseconds without stating its refresh dependence. [PR #86](https://github.com/AgonPlatform/agon-docs/pull/86) removes that unconditional label and adds the conversion and pacing example. The patch is preserved in [MOS-CLOCK-DOCUMENTATION.patch](MOS-CLOCK-DOCUMENTATION.patch). No upstream firmware or MOS code was changed.
