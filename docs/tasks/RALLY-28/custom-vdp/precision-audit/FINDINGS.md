# NUM-001 — Rally numerical-precision findings

The current native renderer already combines integer/fixed-point geometry with a small hardware-float32 road-endpoint stage. It is not doing software-double projection per pixel. The strongest immediate finding is a signed16 conversion hazard introduced by typed native state; zero-steering fixtures do not exercise it. There are also specific removable float conversions/zero operations and reusable lookup work. Wide checked physics and compatibility serialization need separate treatment: casts in source do not equal slow library calls, and some intermediates genuinely need more precision than their stored results.

This is a static audit for VDPlet advice. No application changes, compilations, tests, simulator runs, hardware operations or new instrumentation were performed. Short host parsing reconstructs retained assets and counts retained instruction sites; it does not execute game arithmetic. All proposed validation below is unrun. The preceding hardware task was completed, recorded and released before this audit began.

## Required ranges, semantics and error boundaries — RET-004/005

1. **Wrapped position is small; intermediate coordinates are not interchangeable.** Fuji lap3276800 centiworld; legal wrapped position0..3276799 fits22unsigned bits. At its maximum, eZ80 position→Q8 yields8388605, only2 below signed24 maximum. Adding even64-world lookahead16384 exceeds signed24. Reducing to interval+local coordinates or wrapping before an added lookahead can help, but replacing every s32 station/Q8 expression with s24 is unsafe. Long-lived unwrapped distance/progress and counters have different ranges: a u24 distance accumulator wraps after16777215 units (about388s at360units*120steps/s), well before u32. Keep accumulation precision or explicitly redesign its wrap semantics.
2. **Route sine has a strong local bound.** Legal heading guard is[-32768,32767]; reflection maps magnitude into0..16384 and index0..256, interpolation fraction0..63. Sine table0..32767, adjacent difference at most201, interpolation product at most12663. Fixed six-route trajectory has heading[-1920,1920], speed150..180, so |sine|<=5998 and |speed*2*sine|<=2159280; under the broader full-heading guard that product can reach11796120, beyond signed24 but within s32. Distinguish trajectory proof from generic allowed input. Symmetric route integration can justify tighter state ranges, but this audit does not replace all cumulative/error guards with fixture-only assumptions. Generic signed overflow checks and poisoned-session behavior remain observable on malformed inputs.
3. **Literal lookup products require care before division.** Reconstructed Fuji records: a[-28,20605], b[-6488,13748], c[-61932,77934], d[-6683,9570], e[-2287,943]. Local0..6399 gives f14<=16381, f<=4095, ff<=4094. f*f can reach16769025; b*f can exceed56million and d*f39million. Signed24 multiplication is insufficient even when the quotient is small. A conservative per-record interval bound gives |A|<=82986, |B|<=83009, |B*q|<=10625152 for q<=128 and |centreQ8|<=747059. Native s32 is ample. That conservative bound alone does not prove the correlated B*q actually exceeds24bits, but it does not justify narrowing it. Coefficient c cannot generally be s16. Cached final centres might be narrower after proof; multiplication must widen **before** loss. Do not divide operands early: it changes signed truncation and pixel thresholds.
4. **Road boundaries are exact discrete output.** y104..224, bandheight1..120, offsets[-106,106]. Conservative centre bound gives centres within roughly±2919pixels, so finite float conversion and int32 subtraction are safe. Boundary offsets are exactly representable in float32;1/50 is not. Top/bottom truncation, row coverage yt+1..yb and edge ceil must be preserved. Edge remainder0..height-1 and error before correction<2height fit small storage, but32-bit native registers already execute these operations; packing to16bits is not an established speed win. Clipping0..320 is a different precision boundary from world geometry.
5. **Tangent cross products need wide integer intermediates.** Actual track tx/ty are within[-4096,4096]. Interpolation difference*16383 is at most134209536 with an independent component bound; a cross-product difference is bounded by33554432. Those exceed signed24 while fitting s32. heading() clamps cross to±4096; keep that clamp and sign branch. Source map x[-6111,5723], y[0,4208] already demonstrates distinct map-coordinate/Q8position ranges. Nearby-difference/local-coordinate algebra is a candidate, not permission to narrow before subtraction/multiplication.
6. **Projection, view and sampling thresholds must stay intentional.** Cars z64..1100world, so q7..125 and even Q8scale14..250. Sign range64..500 plus clip checks; player lateralQ8±38400 and opponent lateral±14260 are explicit. Raw lateral difference can reach52660, so signed16 difference/absolute is insufficient even though each opponent field is s16-compatible. Collision is strict |wrapped separation|<3200 centiworld AND |lateral delta|<6144Q8; equality is no contact. Half-lap tie uses >, not>=. Quantized yaw uses(offset+672)/1344 capped4; signed bearing/heading interpolation and asymmetric mirror anchor50/51 must survive. Sampler map99entries, car99×75/sign62×62 backs, source102×77/64×64; mirrored source index uses ceil. Approximate reciprocal/half-float is not a drop-in exact sampler.
7. **Rules/HUD counters are not visual approximations.** Phase crossing precedes timeout, per-tick score remainder and remaining/120 bonus are exact. Score cap9999999 exceeds signed24 maximum; u24 can store it, s24 cannot. u32 lapse/progress products must widen before multiplying. HUD ticks*100 is safe for current bounded races but wraps u32 above42949672ticks (~99.4h at120Hz); no need to narrow because the displayed string is short. A later long-session design can use quotient/remainder formatting. Clock/percentage text is integer-only; float formatting is not a hot-loop issue here.
8. **Colour/resource/ABI fields are not approximate numerical data.** RGB222 low6bits and sync high2bits, XOR2 physical address, bitmap IDs, offsets, handle/token/generation and root byte layout remain exact. Ordinary narrowing casts for wire byte extraction are intentional serialization. Native row lease lifetime and stock output fences must remain unchanged by numeric optimizations. Floating resource IDs or packed pointers would solve no arithmetic problem.

## Concrete signed16 hazard — correctness priority

At checked.c:7, signed16 expects an unsigned value0..65535. At lines231/232, native_validate passes `(uint32_t)w->renderSteering`, but the field is already int16_t. With semantic steering=-21, integer conversion yields4294967275, `(int32_t)v` is-21 on the selected target, then the helper subtracts65536 and produces-65557. Legal negative steering is rejected. Zero-extended original65515 would correctly produce-21. Baseline get16→signed16 has that original zero-extended precondition; the typed substitution broke it. renderer_hook:887 has the same unnecessary conversion chain and then narrows again; do not rely on a second narrowing to recover the desired bits.

This is a static, target-semantic witness, not a new failure from the running fixture. All current900-frame cases force steering0 and Init normally sets it0; neither their passes nor the prior pixel comparison demonstrate negative-steering behavior. Correct later change is to use the already-signed field directly, or explicitly mask to16bits before the old decoder if that boundary must remain. Validate at-21,-1,0,1,21 and invalid limits, including Init/import/Render and baseline comparison; retain unsupported/error/session contracts. No fix made in this audit.

## Rejected blanket changes and open evidence gaps

1. Do not migrate all integer/fixed physics to float32 because native FPU exists. Float32 cannot retain every integer beyond16777216; wrapped position might be exact while products, unwrapped counters, modulo and contact ties are not. Maintaining a stable float32 stage is useful for existing edge math, not an instruction to blur rules/counters.
2. Do not substitute float16 globally. Existing units include laps3276800 and products far beyond half range; even local-coordinate precision and pixel/contact ties need an agreed error budget. No retained half implementation/codegen or performance evidence exists for these candidates. eZ80 Agon-maths assembly is a separate option for a genuinely floating stage, not a reason to replace exact route/lookup logic.
3. Do not mechanically change signed `/2^n` to shifts. C truncation toward0, arithmetic-shift floor, custom edge positive remainder, road nearest and mirror ceil are distinct. Nonnegative sine fraction setup can use shifts, and compiler may already do so; inspect retained code before counting savings.
4. Do not delete64-bit overflow detection based only on3600valid steps. Generated comparisons define error semantics for wide imported state; high-product instructions still implement some needed guard work. Where route/asset range proof makes a guard redundant, propose a narrow change with rejection equivalence, rather than global unchecked math.
5. Compatibility exports still publish root198B scalar data plus96B mutable arrays. State-only four Tickexports+Render global export =1374logical numeric bytes/frame; coarse one Tickexport+Render =492. Buffer metadata/completion add more. These are not float conversions or per-frame UART payload sizes. Removing them is an independently selected production-contract change, not part of this audit.
6. No native phase timestamps or observer-overhead control were added. Hardware allarms30.00MOS/30.058PRTFPS, Flexe nominalPRT39.52/38.59/38.73 and MOS60all do not attribute cost to conversion/checks/rows/sprites. No calibrated speed ratio or spare eZ80 compute claim. Preserve the raw distributions and existing overlapping guest buckets.
7. This audit deeply covers the selected Fuji full-race baseline/state/coarse code. Oval asset contents, arbitrary runtime-mutated tables, unrestricted malformed private state, all playable settings/long-session limits and eZ80 per-site emitted instructions need further selected validation before broad narrowing. Shared source paths identify overlap with standard VDP; they do not prove that every historical experiment uses the same code or has equivalent compiler flags.
8. Numerical changes and generic runtime services are separate ownership. VDPlet should advise on sequence/requirements after review. Rally implements only a later selected change. Existing source/binaries/results/PSRAM/ABI/callback/pixel oracles remain untouched; no compilation, tests or new benchmark was selected by this report.
