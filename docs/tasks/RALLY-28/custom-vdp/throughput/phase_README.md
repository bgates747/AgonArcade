# Native phase diagnostics

These two short diagnostics separate native simulation, command preparation and actual resident drawing stages without changing firmware or the SDK. Both target modules build within the existing limits and pass ordinary and sanitized host checks. Raw counter progress and rendering behavior still require a silent Flexe run. These instrumented fixtures are separate from the 900-frame headline comparisons and establish no hardware frame rate.

1. `phase_build.py` derives control and float/quad/layered packages from the frozen paced-road sources. It adds private native entries 60000–60008 using the existing INVOKE protocol. Each diagnostic performs 128 renders / 512 physics ticks by default; `--frames 64` selects a separate smaller fixture. The original eZ80 driver is unchanged. Its 130 marks use 390 bytes per original 3,000-byte clock array; 39,430 retained reply bytes fit its 50,000-byte transcript. Firmware, SDK service definitions, simulation formulas and actor/player drawing remain unchanged.
2. `phase_clock.inc` reads the Xtensa per-core CCOUNT and PRID registers. Four Tick120 entry durations and the complete Render30 entry duration are recorded, together with nested road/actor/player list-construction durations. Intervals include interrupts and scheduling while those calls run. No assumed MHz conversion is provided. The pinned Flexe interpreter/JIT has source support for these reads and accounts for native-chain instruction prefixes; that supports this diagnostic design, not a runtime calibration claim. The host uses an explicit fake counter for state/protocol checks only.
3. A resident buffer 50306 calls seven silent private markers around clear/title, road, actors, player, an empty marker-to-marker control, and swap. Stock drawing flush bytes are exactly `23,0,CA` (hex). Each buffer call is followed by a flush before its end marker. This closes any pending quad path and drains stock drawing before the timestamp. All marker calls and drawing calls reside in one preloaded tail, so no UART/reply gap is inserted inside these brackets. The intervals still include stock command dispatch, native marker plumbing and flushing; they are not exclusive rasterizer cost.
4. In the pinned stock path, a double-buffered swap queues a controller primitive and waits for a task notification sent after the controller executes `swapBuffers`. The diagnostic adds the ordinary drawing flush before its final marker. The resulting interval therefore brackets controller swap execution by source order. It does not time completion of physical monitor scanout. `phase_SOURCE.json` records the source hashes and evidence; actual runtime ordering/counter progress remains unqualified until the new fixture runs.
5. Buffer 50305 is originally the module upload staging buffer. It is cleared/reallocated only after successful LOAD, which has copied the module into its separate executable allocation. It then holds a 32-byte header and 128 × 52-byte records. Each record contains a frame number, five local-duration counters, then seven stage timestamps. An acknowledged READ16 checks the committed row count after each resident tail, before the foreground clock mark. It adds diagnostic turnaround outside the native stage brackets and catches quiet-marker failures immediately. Full record readout occurs after the measured loop. The fixture creates its ordinary reply/MOS/PRT/clock files; `phase_verify.py` reconstructs the phase records from saved replies. At normal completion it clears its private log/tail buffers. Previous fixture inputs and result files are untouched.
6. Sequence checks require exactly four physics calls and one fresh Render30 before each seven-marker chain. Missing/short log storage, marker order, capacity overrun, unsupported entry and malformed argument checks are host-tested. Failed silent marker calls latch a private error; the acknowledged final sequence check fails the guest instead of silently accepting incomplete records. Observed PRID must remain unchanged; modulo 32-bit interval checks reject ambiguous long spans. Back-to-back counter reads must show positive bounded progress in a target run.

From the project root:

```bash
.venv/bin/python docs/tasks/RALLY-28/custom-vdp/throughput/phase_build.py
.venv/bin/python docs/tasks/RALLY-28/custom-vdp/throughput/phase_qualify.py
.venv/bin/python docs/tasks/RALLY-28/custom-vdp/throughput/phase_source.py
.venv/bin/python docs/tasks/RALLY-28/custom-vdp/throughput/phase_verify_tests.py
```

`phase_BUILD.json` lists complete fixture paths, hashes and target resource sizes under ignored `.work/phase-build/`. `phase_HOST-ordinary.json` and `phase_HOST-sanitized.json` preserve independent traffic/contact checks, exact full-state/output comparisons and the expected final 128-frame state. The separate runner hook is:

```bash
.venv/bin/python docs/tasks/RALLY-28/custom-vdp/throughput/phase_run.py .emulator/<fresh-phase-profile>
```

The parent stager must copy a complete fixture and pin its runtime before this explicit invocation. `phase_run.py` rejects enabled boost before changing run outputs, forces both SDL drivers to `dummy`, delegates finite launch/cleanup to the hash-checked snapshots under `support/`, then performs phase and independent final-state checks. `RUNNER-PINS.json` pins both support files. Runtime imports use only `phase_shared.py` and these snapshots; they never import an old native-demo builder or verifier. The phase builder uses its own small `phase_tape.py` encoder. Existing source on another machine is preserved. The runner never changes boost or other power settings. No diagnostic profile has been launched by this work. Human-visible review and hardware tests remain later gates.

Report native CCOUNT deltas, foreground nominal PRT/MOS time, and host duration separately. The existing host runner includes startup/teardown; phase-readback records are retrieved after the measured loop. Do not subtract timestamps from different clocks, treat source analysis as actual CCOUNT progress, or extrapolate Flexe counter values into hardware milliseconds.
