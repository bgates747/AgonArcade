# RALLY-28 — Native bitmap road improves fenced throughput by 69%

The strongest candidate completes this finite native Fuji fixture at **25.91 nominal MOS FPS**, versus **15.33** for the previous best quad renderer, a **69.05% gain**. These are pooled, completion-fenced, foreground-unpaced Flexe runs on Oryx with CPU boost disabled. The desired 60 Hz rate remains unmet. The Author subsequently reported that visual correctness passes; identical-byte hardware performance remains open.

| Completion-fenced variant | Runs × frames | Nominal MOS FPS | Nominal PRT FPS |
| --- | ---: | ---: | ---: |
| Original triangle/layered control | 1 × 900 | 14.04 | 13.57 |
| Previous best float/quad/layered | 2 × 900 | 15.33 | 14.81 |
| Native spans → RGBA2222 bitmap | 2 × 900 | 20.52 | 19.82 |
| **Same spans → stock Native bitmap** | **2 × 900** | **25.91** | **25.04** |

Pooling divides total completed frames by total elapsed seconds. The quad/RGBA/Native order was reversed for the repeat. Native's individual fenced results are 26.05 and 25.78 FPS. All variants retain controller swap/VSync; foreground-unpaced does not mean display synchronization was removed. [All runs and pooling](EMULATOR-RESULTS.json), [reproduction](report.py).

1. **The change.** The native helper fills a once-allocated 320×120 image using clipped horizontal material spans, then emits one stock bitmap plot. It preserves the original float endpoints, band partition, generated simulation, traffic, player and finish/HUD commands. The second improvement uses the stock Native bitmap copy path: bitmap creation format byte 1 becomes 3. The native module, pixel data and matching scripts are identical between RGBA and Native variants. This avoids RGBA per-pixel conversion/callback work in the pinned firmware. It remains a bitmap copy, not direct access to the display buffer or a new firmware service. [Span implementation](span-README.md), [Native source/layout proof](native-FORMAT-PROOF.json), [exact byte differences](NATIVE-CASES.json).
2. **Costs and restrictions.** The image uses 38,400 bytes of VDP memory; native text/data are 30,928/1,004 bytes. Mean resident road-command bytes fall from 1,799.29 to 45.4. Recurring eZ80 outbound traffic remains 248 bytes/frame before the separately identified fence. Pixel storage and bitmap creation add 38,427 setup bytes outside timing; no pixel uploads occur in the hot loop. Native byte equivalence is specific to pinned mode 136 / VGA64, its negative sync polarities, the fixed opaque palette, Set plotting and disabled affine transforms. Other modes, palettes, transparency or transforms require a fresh proof. Real PSRAM/cache/copy costs may differ substantially from Flexe.
3. **Correctness and runtime.** Fifteen successful 900-frame / 3,600-tick headless runs pass all 2,913 retained reply records, checked suppressed replies, exact independent final-world buffers, timer restoration, input hashes and clean backend exits. Two separate 128-frame / 512-tick phase diagnostics also pass. Ordinary and ASan/UBSan host replay each match all 900 stock-quad road images, with 490 edge cases, 598 section cases, six invalid cases and 126 failure/lifetime cases; leases balance at a peak of four. Runtime INFO17 minimum-free-stack observations start at 2,260 bytes; span variants finish at 2,084, and fenced Native at 2,052 in both runs. These are observed watermarks for this fixture, not exhaustive stack bounds. The final captured scene contains the road, cars and player; Author motion acceptance remains separate. [Host proof](span-FINAL.json), [raw evidence](evidence/), [final image](NATIVE-FINAL.png).
4. **Completion and clocks.** Each fenced frame adds an ordered checked READ16 after drawing/controller swap and before its foreground timestamp: 17 outbound bytes plus ten reply-payload bytes, before packet envelopes. Its successful response proves prior controller work completed; it does not observe physical monitor scanout. Fence/transport overhead is included. The unfenced Native run reaches 26.87 nominal MOS FPS, but is not the primary completed-frame result. MOS uses nominal 120 units/s; PRT uses the nominal 18.432 MHz emulated instruction clock and reports about 3.4% lower FPS. Neither is silently substituted for host wall time, which includes startup/readout/teardown. [Fence proof](COMPLETION-FENCE.json).
5. **Where time went before this change.** In the separate short quad diagnostic, road and actor drawing account for 42.56% and 34.54% of measured work excluding swap; four physics calls plus preparation account for 4.39%. Construction subintervals are nested and are not added twice. Swap includes waiting and varies with display arrival phase. CCOUNT measures abstract emulated instruction progress, not calibrated ESP32 physical cycles; 0xCDCD is Flexe's intentional core-zero token. These phase shares describe the control/quad probes, not the new bitmap candidate's remaining bottleneck. [Interpretation](phase_INTERPRETATION.md), [counter analysis](phase_ANALYSIS.json).
6. **Preserved failure and power handling.** One original-control attempt stalled while uploading startup artwork, before native LOAD, physics or rendering: 50,840 of 58,879 artwork bytes. Its exact prefix and logs are preserved; the same fixture bytes passed in a fresh profile. No emulator fix is claimed. All automated runs forced both SDL drivers to dummy. With explicit Author approval, the supervisor temporarily set boost from 1 to 0 and restored 1 after each session, after all owned emulators stopped. All campaigns share one host boot; maximum sampled temperature was 63°C. [Startup failure](STARTUP-FAILURE-hzbase01.json), [session receipts](SESSION-hzsession03.json).
7. **Preservation and next gate.** All preexisting dirt/task scope was committed and pushed as 39a546a before implementation. All 61 frozen control files, the previous candidate archive, production game binary, firmware and accepted SDK/compiler remain unchanged. New implementation/evidence is uncommitted for review. A fresh, quiet, stopped Native-format fenced profile is ready on Oryx, with sound disabled and the startup line blanked; timed script and driver are unchanged. [Visual-review instructions](HUMAN-REVIEW.md), [final verification](EMULATOR-VERIFICATION.json). No physical card was written or firmware flashed.

This workload deliberately has a flat background and four scripted physics steps per rendered frame. Around 26 FPS therefore delivers about 104 such steps/s in this coupled fixture; it establishes no independently scheduled 120 Hz game loop. It is not the full playable R27 game. The useful next gate is Author motion review followed by identical-byte hardware comparison of the fenced quad control and Native candidate. Further drawing work should first measure the candidate's remaining costs; actor transform/plot work is a concrete follow-up lead from the older phase probes.
