# Wolf3D reference framerate on Oryx

Measure actual completed Wolf3D frames under silent headless Flexe before using its playable behavior as a reference for Rally. The client caps submission and simulation at 30 Hz; that is not a measured rendering rate. The game uses a native ESP32 raycaster for a 256×160 view inside a 320×240 double-buffered display.

1. Preserve the dirty Wolf3dOrig checkout. Copy its previously deployed 105,122-byte playable application and assets, plus the existing matching Wolf VDP firmware/ELF, into a fresh project-owned Oryx profile. Do not substitute the newer unaccepted intermission binary. Restore the original E1L1 spawn only in the isolated medium state package; current packages otherwise start at the diagnostic elevator.
2. Use the already qualified Flexe frontend/adapter and official MOS 3.0.2. Force SDL_VIDEODRIVER=dummy and SDL_AUDIODRIVER=dummy. Apply the previously approved temporary boost-off/restore procedure with temperature monitoring and clean process teardown.
3. Inject ordinary SDL key events through Flexe's PS/2 model to navigate the unchanged menus and hold Right during measurement. This keeps the camera dirty and exercises all view directions; no translation or modified game rules. Record two consecutive 30-second host-clock windows after warmup.
4. Count unique, consecutive W3DR event-one renderer completions and corresponding C3 presentations. Preserve raw UART captures and timestamped observation batches. Captures flush at 250 ms intervals, so disclose endpoint batching uncertainty. Exclude loading, menus, death/fizzle and startup from the measured window. Do not use the emulator's VGA scanout count as game FPS.
5. Verify the final scene, camera-pose changes, callback sequence, backend faults, runtime/input hashes, silent/headless environment, boost restoration and stopped processes. Report workload-specific host-observed FPS separately from nominal 30 Hz policy. No hardware performance or maximum unpaced capacity claim; no optimization or commit/push.
